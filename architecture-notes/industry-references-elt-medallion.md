## Correction: Gold's SCD Type 2 needs a surrogate key and a current-row flag

`valid_from`/`valid_to` alone is an incomplete Type 2 implementation by Kimball's own definition. The full pattern:

- The **natural/durable key** (Huginn: the resolved company's domain) stays stable across every version of that company.
- Each version gets its **own surrogate key** (a new row ID/PK) — the natural key alone can't be the primary key once multiple rows describe the same company over time.
- Each row carries `valid_from`, `valid_to` (null = current), **and** an explicit `is_current` boolean — Kimball specifies the flag *in addition to* the date range, not as a substitute for it. The flag makes "give me the current row" a simple predicate instead of a `valid_to IS NULL` (or `valid_to = 'infinity'`) check scattered across every query.

This refines, not reverses, what's already decided — the versioning trigger (hybrid Type 1/Type 2 columns) and the decision to version Gold but not Silver both stand unchanged.
